# Fridge Cig Report — build brief for Claude Code

An app for rating the Diet Coke at restaurants, bars and gas stations, and ranking every spot on a shared leaderboard. "Fridge Cig" is the app's name; Diet Coke is only ever mentioned descriptively.

`prototype/fridge-cig-report.html` is a working single-file prototype built in claude.ai. Treat it as the **source of truth for look, copy and scoring logic**, and rebuild it as a real web app (phone-first) with accounts, a database and a map.

## 1. What the prototype does today

- **Rate a pour** form: Establishment, City, Format (Fountain / Can / Plastic bottle / Glass bottle), Ice type (Nugget / pellet, Crushed, Cubed, Crescent, Shaved, No ice), Date, four 1–10 sliders, Notes (max 500 chars).
- **Crispiness** score, computed live as a weighted average:
  `fizz × 0.30 + syrup ratio × 0.30 + chill × 0.25 + ice × 0.15`
- **Verdict tiers** from Crispiness: ≥ 9 Elite pour · ≥ 7.5 Solid · ≥ 6 Passable · ≥ 4 Flat-adjacent · below 4 Avoid.
- **Leaderboard**: pours grouped by place + city (case-insensitive), ranked by average Crispiness, ties broken by number of pours. Each row shows city, pour count, format chips, a score bar, and expands to individual pours (score, format, ice type, rater, date, the four sub-scores, notes).
- People can delete their own pours, using an inline confirm step rather than a browser dialog.
- Empty, loading and "view-only" states are designed and worded.

**Platform-specific code to replace:** persistence uses the claude.ai artifact runtime (`window.claude.use('db')` and `use('user')`, a `ratings` collection subscribed with `onSnapshot`). There is a `localStorage` fallback (`dcpr.v1`) that runs when that runtime is absent, so the file works standalone in a browser. Swap both for the real backend below.

## 2. Data model

`pours` (one row per rating):

| field | type | notes |
|---|---|---|
| id | uuid | |
| user_id | uuid → users | owner; only they (or an admin) can edit/delete |
| place_id | → places | replaces free-text place + city |
| format | enum | fountain, can, plastic_bottle, glass_bottle |
| ice_type | enum | nugget, crushed, cubed, crescent, shaved, none |
| fizz, syrup, chill, ice | int 1–10 | |
| crispiness | numeric | store computed value; recompute if weights change |
| notes | text ≤ 500 | |
| poured_on | date | |
| created_at | timestamptz | |

`places`: id, google_place_id (unique), name, address, city, lat, lng.
`profiles`: user_id, display_name, home_city, favorite_format, avatar (optional).

## 3. Roadmap, in order

1. **Stack.** Suggested: Next.js (or Vite + React) + Supabase (Auth, Postgres, row-level security). Firebase is an acceptable alternative. Deploy on Vercel or Netlify. Make it an installable PWA, since most use will be on a phone at the counter.
2. **Accounts and profiles.** Email magic link plus Google/Apple sign-in. Profile page: display name, home city, favorite format, the person's pour history, and personal stats (average Crispiness, most-rated spot).
3. **Place search.** Google Places Autocomplete on the Establishment field; store `google_place_id`, address, lat/lng. This fixes duplicates ("McDonald's Elmwood" vs "McDonalds - Elmwood Ave"). Keep a manual-entry fallback.
4. **Map.** Leaflet + OpenStreetMap tiles (free), or Google Maps if already using Places. One pin per place, colored by average Crispiness tier, with the popup showing score, pour count and a link to the place's pours. Add "Near me" sorting.
5. **Port the UI** exactly as designed (section 4). Leaderboard filters: city, format, ice type.
6. **Nice-to-haves:** photo per pour, "nugget ice" bonus toggle in the Crispiness math (undecided, ask Connor), share a pour as an image card.

## 4. Design system (keep it)

Single cream theme on purpose: it does **not** switch to dark mode.

- Colors: background `#f3e8d0`, card `#fbf5e6`, sunken `#efe2c6`, ink `#2b1d14`, muted `#7a6550`, rule `#d9c6a0`, red `#c8102e`, deep red `#9e0b22`, soft red `#f2d5cc`. Faint dot-grain texture on the page background.
- Header: red enamel "sign" panel with a cream inset border and a 3px deep-red bottom shadow. It holds an eyebrow line, the descriptor "A Diet Coke rating guide", the wordmark, an intro sentence, and a cream "Rate a pour" button.
- **Wordmark:** "Fridge Cig Report" as inline SVG in shaded Spencerian script, generated by `tools/wordmark/make_wordmark.py` (current settings `--nib 21 --track 40`, CSS stroke-width 3). Face is cream, with a deep-red drop shadow offset (5, 7).
- **Type:**
  - Script (Pinyon Script, Google Fonts): wordmark, establishment names, Crispiness verdicts only.
  - Block (Federo, Google Fonts, single weight, so never faux-bold): everything else. Uppercase for labels, headings, buttons, chips and the rank/score numbers; deep red for section headings.
  - Spacing: `letter-spacing: -0.03em` on uppercase Federo; `word-spacing: 0.18em` on the body.
- Layout: leaderboard left, form right; stacks to one column under 820px. Form fields are 42px tall, including the date input (iOS needs `appearance:none` on it).

## 5. Legal guardrails (don't undo these)

- Do **not** use the Coca-Cola or Diet Coke logos, the Coca-Cola Spencerian logo script, the "dynamic ribbon" swoosh, or Coca-Cola's proprietary "You" / TCCC Unity typefaces. Do not use the "Loki Cola" or "Coke4U" clone fonts, which are personal-use only and imitate the trademark.
- App name stays **Fridge Cig Report**. "Diet Coke" appears only descriptively, never as the app's name, domain or app-store title.
- Keep the footer disclaimer: *"Fridge Cig Report is an independent fan project. Not affiliated with or endorsed by The Coca-Cola Company. Diet Coke is a trademark of The Coca-Cola Company."*
- Before monetizing or submitting to an app store, Connor plans a quick trademark-attorney review.
- Fonts are all SIL OFL (free for commercial use). The wordmark is derived from Pinyon Script; its license is in `tools/wordmark/OFL.txt`.
